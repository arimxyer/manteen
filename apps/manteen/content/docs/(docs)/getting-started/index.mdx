Manteen installs source code into an existing application. The source remains visible and editable;
Mantine itself stays an ordinary package dependency.

## Requirements

- Node.js 22.12 or newer
- A Vite, Next.js, or framework-mode React Router application
- The package manager already used by that application

## Set up your project

<Steps>
<Step>

### Install Manteen

Install the consumer CLI as a development dependency:

```npm
npm install --save-dev manteen
```

Confirm the project-local binary is available:

```npm
npm exec -- manteen --version
```

</Step>

<Step>

### Initialize the project

Run initialization from the application root. Preview the complete plan before applying it:

```npm
npm exec -- manteen init --dry-run
npm exec -- manteen init
```

Manteen detects Vite, the Next.js App or Pages Router, a valid Next.js hybrid, or framework-mode
React Router. It adds the shared Mantine setup while preserving the framework's generated entry
structure.

<Callout title="Complete reported manual work" type="warn">

Read every required-work notice before calling initialization complete. For example, an existing
Tailwind PostCSS pipeline can require a small project-owned integration step that Manteen reports
without rewriting the file.

</Callout>

</Step>

<Step>

### Inspect and install an item

Initialization configures the reference `@house` registry. Discover an item, inspect its contract,
and preview the installation before writing source:

```npm
npm exec -- manteen list --query article-card
npm exec -- manteen info @house/article-card
npm exec -- manteen add @house/article-card --dry-run
npm exec -- manteen add @house/article-card
```

The install can add multiple source files, npm dependencies, package stylesheet imports, and a
theme contribution as one planned operation. It does not decide where your application should
render the installed component.

</Step>

<Step>

### Keep the maintenance state together

Commit the installed source together with `manteen.lock.json` and `.manteen/bases/`. The receipt
records ownership and the bases preserve exact pristine source for future comparisons and updates.

Then verify both Manteen's state and the application itself:

```npm
npm exec -- manteen status
npm exec -- manteen diff
npm run build
```

<Callout title="Manteen health is not application proof">

A healthy Manteen status does not prove that the application typechecks, tests, or builds. Use the
checks required by the project for application-level proof.

</Callout>

</Step>
</Steps>
