## Release boundary

`0.5.0` is a client-only maintenance release for D41's automatic conservative AST-assisted merge
fallback. Line diff3 remains the first path for every ordinary file. Only a remaining `.ts` or
`.tsx` conflict may enter the fallback, and `diff` and `update` share that exact decision path.

The fallback parses base, local and incoming source read-only, identifies stable unique imports
and exported top-level declarations, proves both complete sides reconstruct byte-for-byte from
original source ranges, and combines only disjoint changes. It never prints or formats an AST.
Same-key edits, additions/deletions, renames, kind changes, duplicate ambiguity, parse uncertainty,
unowned trivia and other unproven mappings preserve the original diff3 conflict and ranges.

This release does not change `manteen-kit@0.2.0`, the client dependency on
`manteen-kit@^0.2.0`, receipt version 3, registry wire/schema or content, removal semantics,
verification, or project initialization. It creates no kit tag. The public CLI documentation does
change, so publication should include one separately authorized Pages dispatch; that build
re-emits the unchanged 22-item registry alongside the updated docs.

## Candidate and publication sequence

1. Bump only `manteen` and the workspace lock entry to `0.5.0`; keep the kit at `0.2.0`.
2. Move the AST fallback changelog under `0.5.0` and update the candidate/release documentation.
3. Pass the complete local suite and `guard-release --tag manteen-v0.5.0` against the built packed
   surface.
4. Merge one release-candidate PR after its one required hosted matrix passes.
5. Create and push the signed `manteen-v0.5.0` tag at that exact merge commit.
6. Require the credential-free tagged release workflow to pass before reading npm as evidence.
7. Verify npm metadata, tarball integrity and SLSA provenance independently, then install exact
   public `manteen@0.5.0` in a fresh disposable consumer and exercise both an accepted adjacent
   TypeScript merge and an ambiguous refusal against controlled registry revisions.
8. Dispatch Pages once, then verify the public CLI/getting-started documentation and the unchanged
   registry index/item endpoints from the deployed artifact.

Steps 5–8 are publication actions, not part of release preparation. A packed candidate, green PR,
merged version bump, or pushed tag is not public-package or public-documentation evidence.
