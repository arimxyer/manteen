# Manteen client 0.9.3 release handoff

[Documentation map](../project-context.md) · [Release receipts](README.md)

Status: complete and public on 2026-09-01. The client package, hosted portability matrix, signed
tag, npm provenance, and fresh public Vite 7 consumer are accepted. This client-only release did
not change or tag `manteen-kit`, deploy the Fumadocs application, or publish `public/r/`.

## Release boundary

PR [#48](https://github.com/arimxyer/manteen/pull/48) merged the release candidate at
`d67258fa3cd1336e37032679cd99960445aa598c`. The signed annotated tag `manteen-v0.9.3` points to
that merge commit and verifies against the maintainer's configured SSH signing key.

This patch replaces the generated Vite 8-only resolver member with an explicit absolute `@` alias
derived from `import.meta.url`. It preserves authored resolver values and refuses conflicting or
dynamic aliases. Offline status now distinguishes invalid JSON, invalid receipt schemas,
unsupported or future versions, and receipt I/O failures, returning sanitized manual recovery
actions in both text and schema-v2 machine output.

The client still declares `manteen-kit@^0.3.2`, so `manteen-kit@0.3.2` remains the public `latest`
and no kit tag or publication was created.

## Fresh public consumer

A clean temporary npm consumer generated by `create-vite@8.0.2` resolved Vite 7.3.6, installed
exact public `manteen@0.9.3`, and resolved its client dependency to public
`manteen-kit@0.3.2`. The digest-bound init preview and apply both completed, the generated Vite
configuration used `fileURLToPath(new URL("./src", import.meta.url))`, and the unchanged generated
application passed `tsc -b && vite build` with Vite 7.3.6.

`npm audit signatures` then verified registry signatures for all 237 installed packages and
attestations for 85 packages. The first audit immediately after publication reached the advertised
attestation URL before that endpoint had propagated and returned 404; the repeated audit seconds
later passed. No package bytes or consumer state changed between those checks.

## Evidence boundary

This handoff proves source, built-Node, hosted matrix, signed-tag, public-package, provenance, and
fresh public-consumer boundaries for the client. It does not claim that the checked Fumadocs build
or generated `public/r/` tree is hosted. Any future documentation or registry publication needs a
separate deployment design, explicit approval, and public-byte acceptance.
