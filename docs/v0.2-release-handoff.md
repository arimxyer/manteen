# Version 0.2 release handoff

Status: **complete — the managed-global-styles contract, 14-item catalog and Carousel/Dropzone
stress cases are public and verified through a fresh npm-plus-HTTPS consumer.**

## Release boundary

Version `0.2.0` is the first release that carries receipt v2 and maintains package-level global
stylesheet imports contributed by registry items. It also publishes the curated eight-item Mantine
UI tranche through the live `@house` registry.

The release sequence is deliberately fail-stop:

1. merge one exact source commit after the full hosted matrix;
2. publish and independently verify `manteen-kit`;
3. publish and independently verify `manteen`;
4. manually dispatch the Pages deployment; and
5. install from public npm and the public HTTPS registry in a fresh consumer.

Pages is dispatch-only. A merge cannot expose registry content that requires a client contract
which has not reached npm yet. `scripts/guard-release.mjs` mechanically refuses an automatic
`main`-push Pages trigger.

## Fresh public consumer receipt

A new Vite React TypeScript project lived entirely under `/tmp` and used npm with the public
`manteen@0.2.0`; it did not invoke this checkout's bundle or a local registry:

```bash
manteen init --yes --framework vite --pm npm
manteen add @house/cards-carousel @house/dropzone-button --yes --pm npm
npm run build
manteen diff @house/cards-carousel @house/dropzone-button --stat
```

The public client fetched the live `@house` URLs, installed the shared license and all declared npm
dependencies, and wrote the four component files plus `src/manteen.css`. Receipt v2 attributed
`@mantine/carousel/styles.css` and `@mantine/dropzone/styles.css` to their respective items. A
harness imported and rendered both components; `tsc -b && vite build` transformed 7,030 modules and
succeeded. The final diff reported `No changes. 5 files unchanged.`

This proves public distribution, live-registry retrieval, dependency installation, managed-style
composition, consumer typechecking and a production bundle for the Vite shape. It does not replace
the earlier multi-framework local builds and browser interactions, newly prove the stylesheet
lifecycle on macOS/Windows, or validate an independently authored second registry.

## Next boundary

The release/deployment boundary is closed. Wc remains an ongoing content program. Its practical
next proof is a second independently authored live registry; after that, continue with small,
attributed content tranches and broaden framework-specific visual acceptance when those fixtures
are available.
